# 三层分支体系说明

> **所属章节**：第三章 三层分支体系：展厅、车间与工位
> **核对人**：组长 宋怀海　**最近更新**：2026-11-13
> **对应要求**：从 `master` 拉出 `develop` 并推上远程；每个组员从 `develop` 拉出自己的成员分支，
> 三层结构就位，并行开发有了交通规则。

## 一、三层结构

| 层 | 分支 | 比方 | 定位 | 谁可以写 |
| --- | --- | --- | --- | --- |
| 1 | `master` | 展厅 | 缺省主分支，存放对外发布的稳定版本 | 只有组长，且只接受 `develop` 的合并 |
| 2 | `develop` | 车间 | 开发分支，各成员分支代码的汇总，放最新完成的功能和修完缺陷的代码 | 组长合并，成员不直接提交 |
| 3 | `shh_branch` 等 | 工位 | 每人一条，从 `develop` 拉出，随便折腾、互不干扰 | 本人 |

## 三、验证命令与输出

### 1. 本地查看三层结构

```console
$ git branch -a
* develop
  master
  shh_branch
  remotes/origin/HEAD -> origin/master
  remotes/origin/develop
  remotes/origin/master
  remotes/origin/shh_branch
  remotes/origin/wjh_branch
  remotes/origin/xy_branch
  remotes/origin/ylx_branch
  remotes/origin/zjh_branch
```

`*` 号是当前所在分支；`remotes/origin/*` 是远程分支在本地的只读副本。

## 四、命名规范

- 格式：`姓名拼音首字母_branch`，如 `shh_branch`（宋怀海）。
- 全小写，不带空格，不用中文，不用 `my-branch`、`lihui` 这类不规范命名。
- 本地文件夹名与仓库名一致，避免中文空格坑。

## 五、纪律与注意事项

1. **成员分支必须从 `develop` 拉**，不要从 `master` 拉——否则合并时冲突面翻倍。
2. **任何人不直接在 `master` 上改代码**。一个人短期"看起来没事"，是在透支全组的冲突额度。
3. **本地建了 ≠ 远程有**：`git push -u origin <分支名>` 之后才算数。
4. 切换分支用 `git checkout <分支>`，新版 Git 也可用 `git switch <分支>`，效果相同。
