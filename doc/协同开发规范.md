# 协同开发规范（日常开发循环）

> **所属章节**：第五章 日常开发循环：pull → 改 → add/commit → push
> **适用范围**：全组 5 人 × 5 条成员分支
> **最近更新**：2026-11-13

## 一、Git 的四个区

| 区 | 位置 | 进入命令 | 比方 |
| --- | --- | --- | --- |
| 工作区 | 看得见的项目文件夹 | 直接编辑文件 | 货架 |
| 暂存区 | `.git/index` | `git add` | 购物车 |
| 本地仓库 | `.git/objects` | `git commit` | 已购买的订单 |
| 远程仓库 | GitHub | `git push` / `git pull` | 云端 |

日常循环口诀：**改一改 → add 进车 → commit 入库 → push 上云；第二天开工先 pull。**

## 二、标准动作（每天照做）

```console
# ① 开工同步：先切回自己的工位，再把远端 develop 的最新进展拉进来
$ git checkout shh_branch
$ git pull origin develop

# ② 干活 + 随时自查
$ git status
$ git diff

# ③ 小步提交：做完一小块就提交，不要攒一周
$ git add doc/xxx.md
$ git commit -m "doc: 第5周数据模型设计文档初稿"

# ④ 下班前推上去：本地仓库不是保险箱
$ git push origin shh_branch
```

## 三、提交说明规范

格式：`前缀: 一句话说清做了什么`。动词开头，说清"改了什么"，禁止"修改了一些东西"这类含糊说明。

| 前缀 | 用途 | 示例 |
| --- | --- | --- |
| `feat` | 新功能 | `feat: 文章点赞功能` |
| `fix` | 修缺陷 | `fix: 评论区空指针报错` |
| `doc` | 文档 | `doc: 第5周数据模型文档` |
| `refactor` | 重构 | `refactor: 拆分 ArticleService` |
| `chore` | 杂务（环境、忽略规则） | `chore: 添加 .gitignore` |
| `merge` | 合并（仅组长） | `merge: integrate zjh_branch into develop` |

> **本组现状（需注意）**：历史提交普遍用的是 `docs:`（多一个 s）。`docs:` 也属通行写法，
> 但本课程统一以 `doc` 为准，**自第五周起新提交一律用 `doc:`**，不再两边混用。

## 四、.gitignore

仓库根目录已建立 `.gitignore`，第五章要求的五条门（永远不让垃圾文件进购物车）：

```gitignore
__pycache__/
*.pyc
db.sqlite3
.idea/
*.log
```

排查"文件推不上去"时，先跑 `git check-ignore -v <文件名>`——多半是被忽略规则挡住的。

## 五、四区自查速查

| 命令 | 看什么 |
| --- | --- |
| `git status` | 哪些文件改了 / 未跟踪 / 已暂存 |
| `git diff` | 工作区与暂存区的具体差异（退出按 `q`） |
| `git diff --staged` | 暂存区与本地仓库的差异（这次提交到底包含什么） |
| `git log --oneline -5` | 最近 5 次提交，检查说明是否合规 |

## 六、三条硬纪律

1. **本地仓库不是保险箱**：换电脑、进机房前必须先 `push`，本地丢了就是真丢了。
2. **不要 `git add .` 无脑全加**：先 `git status` 看一眼，防止把临时文件、密码配置推上远程。
3. **`git add` 之后又后悔**：用 `git restore --staged <文件名>` 退回购物车之前，工作区内容不变。

## 七、每周节奏

| 时间 | 动作 | 负责人 |
| --- | --- | --- |
| 每天 | 开工 `pull`，下班前 `push`；每人每周至少 2 次有效 push | 全员 |
| 周五 | 把本周有进展的成员分支逐个 merge 进 `develop` | 组长 |
| 周五 | 抽查各成员 `git log`，点名提醒攒一周一提交、说明含糊的 | 质量和过程经理 |
| 周五 | `develop` 定版合并进 `master` | 组长 |
| 随时 | 维护 `.gitignore`，帮组员排查推不上去的文件 | 支持经理 |
